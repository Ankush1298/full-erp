# 49 — School onboarding browser rehearsal, attendance UI review and the PR-1 decision

Status: executed 2026-11-07 on a **throw-away** synthetic environment; uncommitted. It approves nothing: PR-1, OD-I1 to OD-I5 and the M3/M4 acceptances stay pending. No persistent database, `.env`, credential, development server or real data was used; no secret (invitation token, MFA ticket or seed, recovery code, password) was printed or stored.

## 1. How it was run

`backend/tests/support/rehearsal-stack.ts` starts a temporary PostgreSQL (random port and passwords, deleted on stop), applies the real migrations, and serves the real API on 127.0.0.1; `backend/tools/e2e/school-onboarding.rehearsal.mjs` also starts the real Vite dev server on a free port and drives **real Chrome** (Playwright Core, installed outside the repository). The "operator" steps call the same services as the platform CLI (`createTenant`, `issueFirstAdminInvitation`, `issueFirstAdminMfaTicket`); an in-memory mailer stands in for e-mail so the rehearsal can obtain an invitation token (G4: no production mailer exists). Your running development servers (ports 4000 and 5173) were not touched. Command: `PLAYWRIGHT_CORE_DIR=<dir> node --import tsx tools/e2e/school-onboarding.rehearsal.mjs` from `backend/`.

## 3. Negative cases (all passed in the browser or at the server)

Expired invitation (refused, user stays INVITED); reused invitation; weak password (token preserved); wrong tenant (school B's token activates only school B, A unaffected); duplicate bootstrap (`ADMIN_ALREADY_ACTIVE`); no ticket / invalid ticket; invalid TOTP at enrolment and at sign-in; MFA ticket after bootstrap closed; **unauthorized institution setup** (the Teacher gets 403 for institution type, terminology, user invitation and campus creation, has no Setup wizard in the UI, and the stored type is unchanged); **cross-tenant** (B's principal gets 404 for A's campus, department and user, sees none of A's users, has no institution type, and keeps default role labels).

## 4. Defects found by the rehearsal and fixed

1. **A wrong or expired MFA enrolment ticket signed the user out of the web app.** The server answers 401 `INVALID_TICKET`; the client treated every 401 as an expired session and dropped to the landing page (the server session stayed valid). Fix: `startMfaEnrollment` is marked `public: true` in `apps/web/src/lib/api/mfa-api.ts`, like the verify and challenge calls the owner had already marked. Regression test in `apps/web/tests/mfa.test.tsx` (fails without the fix, passes with it).
2. **A campus created in the wizard did not appear in the department form without a page reload.** Fix: the department form refreshes with the wizard state (`AcademicSetupWizard.tsx`); test added to `academics-setup-wizard.test.tsx`.
3. Test infrastructure: two web-client path strings in the attendance API client were restructured (no behaviour change) so the repository's web/API contract test can resolve them; one SQL alias in the attendance service was quoted (`fa."role"`) so a static guardrail stops mistaking it for a role comparison; the contract-migration allow-list gained the rehearsal stack (a throw-away database only).

## 5. MFA and invitation security findings

- Tokens are single use and bound to one tenant membership; an expired, reused or wrong-tenant token gives the same generic page error; the invitation token is removed from the address bar after use (`replaceState`) and the page sends `Referrer-Policy: no-referrer` (confirmed in source).
- Bootstrap enrolment cannot be repeated or double-issued; operator output stays local-only.
- Medium: the enrolment dialog's UX conflates step-up and ticket errors (fixed above for the sign-out; the messages themselves are acceptable).
- Open, unchanged: no production invitation mailer (G4); no lost-authenticator recovery for a sole administrator; the login dialog has an optional tenant field but no tenant picker for an identity that belongs to several tenants.
- TOTP replay protection is covered by the integration suite, not re-tested in the browser.

## 9. Update 2026-11-07 — ATT-1, ATT-2 and ATT-3 fixed (attendance time-zone correctness)

Verified, not assumed (backend `m4-attendance-timezone.test.ts` 10 tests, web `campus-time.test.ts` 7 and `attendance-timezone.test.tsx` 16, and the real-Chrome rehearsal 37/37 with the teacher's browser set to America/Los_Angeles and the campus in Asia/Kolkata).

**Root causes.** ATT-1: the session form built instants as `…T09:00:00Z` (it treated typed times as UTC), displayed them in the device zone, and defaulted dates to the UTC date; the backend rightly judges the class's day in the campus zone. ATT-2: the page decided direct correction versus request from a UTC day count while the server (AD-2) counts campus calendar days. ATT-3: every 403 was worded "disabled by institution configuration", and 409s showed "API validation (409)".

**Contract (additive, read-only; stored timestamp semantics unchanged).** `SessionDto` gains `campusTimezone`, `campusToday`, `correctionWindowDays`, `insideCorrectionWindow` (computed in SQL from the campus zone and the same policy row enforcement uses; the server still re-decides every correction, request and approval). `GET /attendance/my-offerings` gains `campusId`, `campusTimezone`, `campusToday`. New `GET /attendance/campuses` (permission `attendance.record.read`) lists, with each campus's clock, only the campuses the caller reads through an institutional grant; assigned faculty and students get none, other tenants never appear. Stable error codes: `ATTENDANCE_CORRECTIONS_DISABLED` (the deployment switch, still default off), `FORBIDDEN` (route permission), `SESSION_LOCKED`, `TERM_CLOSED`, `TERM_NOT_OPEN`, `ATTENDANCE_NOT_SUBMITTED`, `CORRECTION_WINDOW_PASSED`, `CORRECTION_WINDOW_OPEN`, `RECORD_CHANGED`, `NO_CHANGE`, and for scheduling `SESSION_EXISTS`, `SESSION_TIME_OUTSIDE_DAY`, `SESSION_DATE_OUTSIDE_TERM`, `SESSION_ON_HOLIDAY`, `TEACHER_NOT_ASSIGNED`, `TIMETABLE_SLOT_INVALID`, `OFFERING_NOT_PUBLISHED`, `OFFERING_NOT_TRACKED`. Unassigned users still get the same 404 as a missing record (no new information).

**Web.** `lib/campus-time.ts` converts typed campus wall-clock time to a UTC instant with `Intl` only and reports a time that does not exist (daylight-saving gap) or occurs twice as a validation message; dates default to the campus date from the server; times show on the campus clock with the zone named; the correction dialog follows `insideCorrectionWindow`; the register opens on the campus date (with a campus selector when the caller reads several); `lib/attendance-errors.ts` maps codes to plain sentences. No time zone is hard-coded.

**Examples tested.** Asia/Kolkata 09:00 → 03:30Z → reads 09:00; 23:30 stays on the campus date; America/New_York 13:00Z in summer and 14:00Z in winter; Asia/Kathmandu (+05:45), Pacific/Kiritimati (+14), Pacific/Pago_Pago (−11); New York spring-forward 02:30 (does not exist) and fall-back 01:30 (twice); Auckland and Lord Howe gaps; at 20:00Z on 7 November the campus date is the 8th in India and Kiritimati but still the 7th in New York and Pago Pago; window boundary day 3 inside and day 4 outside in four zones, with enforcement agreeing with the flag; a campus policy of 1 day changes both.

**Remaining limits.** ATT-4 (student attendance page) is still deferred; its priority follows PR-1. A class cannot cross midnight (the database guard requires start and end on the session date); the form says so. An ambiguous or non-existent local time is refused rather than guessed. Existing sessions created by the earlier UTC-based form (only on synthetic data) were stored as UTC-typed instants; no real data exists, so no migration or reinterpretation was done.
